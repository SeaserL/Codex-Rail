# 一个盼望被取代的项目

Codex Rail 是一个尽可能轻量的 Windows Codex 用量浮窗，也是一个从诞生起，就期待被取代的项目。

在使用其他 agent 时，我已经习惯了随手看一眼用量。剩余多少、上下文占了多少、什么时候重置——这些信息就放在操作面板里，简单得像呼吸一样自然。回到 Codex，我却发现查看常规额度仍然需要点开头像，再进入使用情况菜单。一个工作时经常需要知道的数字，被放在了需要专门去找的地方。

让我尤其介意的是左边那条长长的侧栏：它留下了大片空白，却没有给这些信息一个位置。放在对话框上沿、顶栏，或者就放在侧栏里，似乎都是很自然的选择。对使用者来说，这看起来不应该是一项值得反复讨论的功能，而应该是打开软件时就在那里的一部分。

我查阅了官方的公开 issue。截至本项目开发时，常驻额度显示的相关需求仍然处于开放状态；我也没有找到适合把第三方组件直接挂进桌面侧栏的公开接口。公开信息无法告诉我 OpenAI 内部在做什么，于是我先做了一个自己能用的答案。

但必须承认，Codex Rail 只是一个手搓的外挂“插件”。它的本体是一个跟随 Codex 窗口的透明浮窗，而不是原生侧栏组件。无论怎样打磨动画、定位、布局与配色，这种叠加都会有割裂，也会有不完美。我可以通过一次次迭代让它更接近理想，却更希望那份理想的答卷由 OpenAI 亲自递出。

也许是哪次更新里，这个功能悄然出现了：更新公告中一笔带过的一行，或者设置页里多出的一个小开关。用量从此就在眼前，不再需要额外的程序。是的，连我自己都盼望这个项目的消亡。它最好的结局，就是变得没有必要。

我知道 macOS 上已有不少菜单栏工具，Windows 也不缺第三方浮窗。这不是第一个尝试，也无意成为唯一的答案。它借鉴了我很喜欢的 Windows 工具 TrafficMonitor 的一些思路：让经常需要的信息贴近正在进行的工作，不打断，也不抢眼。我认为把这些数字安放在侧栏，是最自然的方式之一，于是便这样做了。

经过本地测试和反复迭代，目前的结果让我比较满意，也算给自己的困扰画上了一个不算完美的句号。独立版仍有几十 MB——其中大部分是随包携带的 .NET 运行时；轻量化是继续努力的方向，而不是一张已经兑现的保证书。

希望这个小工具也能帮到有相似困扰的人。也许你是让 AI 搜索“Codex 状态栏”“Codex 用量显示”时找到这里的，就像项目刚开始时的我一样。如果你愿意试一试，读到了这里，并且觉得它确实帮上了一点忙，那就很好了。
